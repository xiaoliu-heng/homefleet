# Agent 版本与后台更新

从 **0.2.0** 开始，安装为系统服务的 Agent 可以在控制台更新。设备总览和「Agent 更新」显示实际上报的版本；左下角是 Hub 版本，两者互不混淆。

## 0.2.3 公开源码整理

采用 MIT 许可证，公开部署示例和测试地址统一使用文档地址。首次启动和重置管理员密码时拒绝示例占位值。构建目录及容器包含 `LICENSE`、`THIRD_PARTY_NOTICES.md`，也可从控制台的 `/downloads/` 获取；分发二进制时请一并提供这两份文件。此版本没有自动升级现有设备。

## 0.2.2 Arch 安装范围调整

安装与更新分开：安装使用已有软件源索引的 `pacman -S --needed`，不刷新索引、不自动执行全量升级；更新仍使用 `pacman -Syu`。安装前通过只读 `pacman -Qu` 检查索引与已安装版本，发现待升级包或检查失败时停止；已同步索引但升级失败的设备必须先处理冲突并完成系统升级。镜像中旧包不存在时不会自动改成全量升级。

预览和执行前都会检查。旧版安装预览需要重新生成；Hub 会提示尚未具备该能力的 Arch Agent 先手动升级到 0.2.2。发布新版本不会自动更新任何设备或修复现有软件包冲突。软件清单缺少工具时明确显示 `checkupdates` 由 `pacman-contrib` 包提供。

## 0.2.1 修复

修复 macOS 账号所属用户组超过 16 个时，Agent 启动 Homebrew 或项目命令出现 `fork/exec ...: invalid argument` 的问题。macOS 用户任务改用系统自带的 `sudo` 非交互切换身份，由系统初始化目标用户的用户组；不会截断成员关系，也不会以 root 执行 Homebrew。项目环境变量通过进程环境传递，保持原有执行目录。

Homebrew 预检查失败现在显示执行账号、检查命令及实际错误，避免把进程启动失败或软件源查询失败误报为未安装 Homebrew / 未找到软件。已安装 0.2.0 的设备可在「Agent 更新」中预览并手动确认升级到 0.2.1，再重新预检查软件任务。

## 第一次启用

0.1.0 没有更新器，不能靠服务端补发一个任务就获得自更新能力。在每台设备的管理员终端重新运行接入页的一键安装命令一次，安装到当前发布版本。已有配置会保留设备 ID、凭据、Hub 地址、CA、运行账号和任务记录，不会创建重复设备。请在设备没有运行中的修改任务或更新器时执行手动安装。

安装器登记 Linux systemd、macOS launchd 或 Windows SYSTEM 服务。普通用户临时启动、只读模式、非标准安装路径不会显示可后台更新。Windows 用户执行器仍以本人账号运行；Agent 更新使用独立 SYSTEM 计划任务，不要求本人保持登录。

## 日常操作

1. 打开「Agent 更新」，查看当前版本和可发布版本，选择设备。
2. 点击「预览 Agent 更新」。设备检查服务身份、平台、版本、磁盘空间和写入权限，列出固定版本、文件大小及 SHA-256。
3. 确认通过检查的目标。默认同时操作最多 3 台，每台设备排队等待其他任务完成。
4. 在任务中心查看逐台结果。只有新 Agent 使用原身份成功向 Hub 上报心跳后才成功；已经是目标版本时不下载、不重启。

不自动定时升级，不允许后台降级。失败目标重试先重新预检查；待核实目标禁止自动重跑。预览固定版本，不会因为服务端随后发布新版本而偷偷更改执行文件。

## 下载地址

自更新使用该设备配置的 `hub_url` 和 `ca_cert`，从 `/downloads/agents/<版本>/<平台文件>` 下载。因此原来使用域名、LAN IP 或 Tailscale IP 的设备继续使用各自能访问的入口，保持 HTTPS 证书校验。下载请求不附带设备令牌。

一键安装仍支持切换下载与连接地址，以及 `--download-url` / `-DownloadUrl` 的独立下载入口；这个参数只用于本次引导安装，不更改已有 Agent 配置。后台更新始终从配置的 Hub 下载。

## 发布新版本

在可信构建机上修改根目录 `VERSION`（稳定的 `X.Y.Z`），然后：

```bash
bash scripts/build.sh
```

该命令把版本通过 Go ldflags 写入 Hub 和四平台 Agent，生成：

- `dist/releases/agent-release.json`：可发布版本、最低更新器版本、平台文件大小和 SHA-256。
- `dist/releases/agents/<版本>/`：固定版本文件；同一版本禁止发布不同字节，代码变化必须升版本。
- `dist/releases/homefleet-agent-*` 和安装脚本：供首次安装、手动更新使用。
- `dist/releases/SHA256SUMS`：引导安装校验清单。

将 Hub、前端和完整 releases 目录一起部署。保留旧 `agents/<版本>/` 目录，直到没有待执行或待核实任务引用它；离线部署要把这些目录一并复制到 prebuilt。普通 Docker 构建只打包当前版本，部署前必须确认旧预览/执行任务已经结束，或在部署镜像中额外保留其固定文件。后台会发现新版本，但不会自行执行更新。

Hub 只读取服务器本地发布清单。浏览器不能提交任意下载 URL 或替换校验和。通过更新发布包来发布版本，首版不提供浏览器上传二进制功能。

## 失败与恢复

下载完成后先检查大小、SHA-256、二进制内置版本及读取现有配置的能力。独立更新器保留原文件，停止 HomeFleet 服务，原子替换文件并启动。Windows 同步停止用户执行器；更新后能启动时重新启动，用户注销时等待下次登录。

新版无法启动或两分钟内没有成功回连时，尝试恢复旧文件并启动旧服务。恢复文件或启动旧服务失败会标记待核实；不会把回退失败报告为成功。突然断电、更新器异常退出或无法确定服务状态时，保留执行记录，阻止自动重复安装。Hub 给升级中的服务重启保留 15 分钟任务窗口，设备离线展示仍按 45 秒心跳规则计算。

升级日志和状态保存在配置 `data_dir` 下的 `journal/`、`updates/`；原文件在安装目录的 `.homefleet-previous-<任务ID>[.exe]`。这些记录和备份不会自动删除。只有确认相关任务结束且不再需要回退时才能人工清理。

待核实时，先在设备上检查二进制 `version`、系统服务状态和日志，再在任务中心记录真实结果。若独立更新器已经退出，可以用安装命令手动恢复；安装器会保留原任务的核实要求并解除本地升级记录的阻塞。损坏的配置或日志需要先从备份核实恢复，不能直接清空状态来重跑。

## 验证范围

自动化测试覆盖真实 HTTPS 下载和哈希拒绝、固定发布版本、浏览器确认流程、真实文件替换、模拟服务启动失败回退、重复投递、意外中断，以及实际编译的新 Agent 进程使用原身份回连并回传结果。Linux amd64 / arm64、Windows amd64、Apple Silicon 已交叉编译。

各操作系统真实系统服务的停启、Windows 注销和用户执行器、macOS launchd 权限及物理断电恢复仍需实机验收；隔离进程测试不能替代这些验收。第一次上线不会批量升级现有设备。
